# Advanced Recommendation System – Design & Enhancements

## 1. Search Data Collection Strategy

### 1.1 Search Box Searches

User searches entered directly in the search bar should be stored as:

* Structured search intent:

  * category
  * sub-category
  * brand
  * price range
  * location (if enabled)
* Timestamp of search

📌 Raw text can be stored temporarily, but **recommendation logic should rely on structured intent**, not plain text.

Example:

```
User types: "Samsung phone under 30000"
Stored as:
{
  category: "Phone",
  brand: "Samsung",
  priceMax: 30000
}
```

---

### 1.2 AI Chatbot Searches (Gemini-based)

Instead of saving the **entire chatbot conversation**, the system should store **only meaningful signals**.

#### ❌ What NOT to store

* Full chatbot text
* Long AI explanations
* Irrelevant conversational content

#### ✅ What TO store (best practice)

**Three-stage intent capture:**

1. **AI-extracted intent** (medium weight)

   * Gemini converts user input into structured filters
   * Example:

     ```
     category: Phone
     brand: Samsung
     priceMax: 30000
     ```

2. **Displayed products**

   * Products shown by chatbot (temporary memory)

3. **Clicked products (highest weight)**

   * Product IDs user clicks after chatbot response
   * This confirms *real interest*

📌 Recommendation engine should rely mostly on **clicked products**, not just AI interpretation.

✔️ **Conclusion**

> Store structured AI intent + clicked products.
> This is far better than saving raw chatbot text.

---

## 2. Review Handling Using Sentiment Analysis

Writing a review does **not always mean interest** — this is a correct observation.

### Correct handling:

* Analyze review sentiment:

  * Positive
  * Neutral
  * Negative
* Generate a sentiment score

### How sentiment should be used:

| Sentiment | Effect                            |
| --------- | --------------------------------- |
| Positive  | Increase seller interaction score |
| Neutral   | No change                         |
| Negative  | Decrease seller interaction score |

📌 **Important rule**

* **Do NOT** increase product or category preference just because a review exists
* Reviews reflect **seller experience**, not product interest

✔️ This keeps the recommendation logic realistic and fair.

---

## 3. New User / Cold-Start Recommendation Strategy

### Case 1: New user (no activity)

**If location is enabled**

1. Nearest products
2. Popular products (views + likes)
3. Trusted sellers

**If location is disabled**

1. Popular by views
2. Popular by likes
3. Recently added products

---

### Case 2: Weak activity (1–2 interactions)

* Similar products to last viewed
* Popular fallback items

📌 This solves the **cold-start problem**, which should be explicitly mentioned in your report.

---

## 4. Price-Aware Recommendation Logic

Price must be treated as a **hard constraint**, not just a ranking factor.

### Example:

If user mostly views:

```
Phones under 30000
```

### Recommendation priority:

1. Same category (phones)
2. Same price range (±20%)
3. Similar brands/specs
4. Trusted sellers

❌ Recommending expensive products breaks user trust
✅ Budget-aware filtering increases conversion

---

## 5. Collaborative Filtering (User-to-User)

User similarity should be calculated using **weighted behavior**:

| Action            | Weight |
| ----------------- | ------ |
| Like              | High   |
| Long view         | Medium |
| Chat with seller  | Medium to high (based on if user chating with same seller about same product , or user have liked that product and chatting in this case weight become highest |
| Review (positive) | High   |

Users with overlapping interests are grouped as **similar users**.

Recommendations include:

* Products liked by similar users
* Excluding products already seen or disliked

📌 This is true **collaborative filtering**, not just popularity ranking.

---

## 6. Additional Enhancements (Recommended)

### 6.1 Time Decay

Recent actions matter more than old ones.

Example:

* Last 7 days → full weight
* Last 30 days → reduced weight
* Older → minimal impact

---

### 6.2 Session-Based Intent

If user suddenly searches a new category:

* Temporarily boost that category
* Do not overwrite long-term preferences

---

### 6.3 Exploration Factor

Inject 10–15% diverse but relevant items to:

* Avoid filter bubbles
* Help discovery
